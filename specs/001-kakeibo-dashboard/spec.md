# Feature Specification: 家計簿ダッシュボード（LINE で見る、銀行明細の自動家計簿）

**Feature Branch**: `001-kakeibo-dashboard`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "銀行 API（sunabar）の入出金明細を使った家計簿ダッシュボード。LINE Bot で今月の支出を返し、リッチメニューから LINE 内で開く画面でカテゴリ別のグラフを見られる。支出のカテゴリ判定・予算・他の金融機関の明細統合は『あったらいいのに』という自作 API で補う。"

## 概要（チームメンバー向け）

家計簿アプリが続かない一番の理由は「入力が面倒」なこと。このアプリは、**銀行口座の入出金明細を自動で取り込み、支出を自動で分類し、普段使っている LINE の中で確認できる**ようにする。

- ユーザーは何も入力しない。LINE でボタンを押すか一言送るだけで、今月いくら何に使ったかが分かる。
- 実在する銀行 API（sunabar）で取得できる明細に加え、「銀行がこういう API を提供してくれたら家計簿はもっと便利になる」という提案を、自作 API として実装・発表する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - LINE で今月の支出サマリーを受け取る (Priority: P1)

ユーザーが LINE のトーク画面で「今月」と送る（またはリッチメニューの「今月の支出」を押す）と、Bot が今月の入金合計・支出合計・支出の多いカテゴリ上位 3 つを、カード形式のメッセージで返す。

**Why this priority**: 画面（ダッシュボード）がなくても、これだけで「自動家計簿」の価値が伝わる最小単位。以降のストーリーが間に合わなくても発表が成立する。

**Independent Test**: sunabar 口座に入出金の記録がある状態で LINE から「今月」と送り、金額が sunabar の明細と一致するカードが返ってくることを確認できる。

**Acceptance Scenarios**:

1. **Given** 今月に入金 2 件（合計 300,000 円）と支出 5 件（合計 45,000 円）がある, **When** ユーザーが LINE で「今月」と送る, **Then** 「入金 300,000 円／支出 45,000 円」と、支出額の多いカテゴリ上位 3 つ（カテゴリ名・金額）が 1 通のカードで返る。
2. **Given** 今月の明細が 1 件もない, **When** ユーザーが「今月」と送る, **Then** 「今月の入出金はまだありません」と返り、エラーにならない。
3. **Given** ユーザーが「先月」と送る, **When** Bot が応答する, **Then** 前月 1 日〜末日の明細で同じ形式のサマリーが返る。
4. **Given** 銀行 API が一時的に応答しない, **When** ユーザーが「今月」と送る, **Then** 「銀行とつながりませんでした。少し時間をおいて試してください」と返り、Bot が無反応にならない。

---

### User Story 2 - LINE 内のダッシュボードでグラフと明細を見る (Priority: P2)

ユーザーがリッチメニューの「ダッシュボード」を押すと、LINE の中で画面が開き、今月の支出をカテゴリ別の円グラフ、日ごとの支出推移、明細一覧で確認できる。月を切り替えて過去の月も見られる。カテゴリを選ぶと、そのカテゴリの明細だけに絞り込める。

**Why this priority**: 「LINE の中で家計簿アプリが開く」体験がこのアプリの見せ場。ただし P1 の集計ロジックが前提になるため 2 番目。

**Independent Test**: LINE のリッチメニューからダッシュボードを開き、表示される合計額・カテゴリ別金額が User Story 1 の LINE のカードと一致すること、月切替・カテゴリ絞り込みが動くことを確認できる。

**Acceptance Scenarios**:

1. **Given** ユーザーが LINE でリッチメニューの「ダッシュボード」を押す, **When** 画面が開く, **Then** LINE の表示名で「○○さんの家計簿」と表示され、今月のカテゴリ別円グラフ・日別支出グラフ・明細一覧（新しい順）が表示される。
2. **Given** ダッシュボードで今月が表示されている, **When** 「前の月」を押す, **Then** 前月のデータに切り替わる。
3. **Given** 円グラフが表示されている, **When** 「食費」を選ぶ, **Then** 明細一覧が食費の明細だけになり、解除すると全件に戻る。
4. **Given** 明細が 0 件の月を表示する, **When** 画面が開く, **Then** グラフの代わりに「この月の入出金はありません」と表示される。
5. **Given** LINE アプリ以外のブラウザで URL を直接開く, **When** 画面が開く, **Then** LINE でのログインを促す案内が表示される。

---

### User Story 3 - 予算と比べて使いすぎに気づく (Priority: P3)

カテゴリごとに月の予算が決まっており、ダッシュボードと LINE のサマリーに「予算に対する使用率」が表示される。使用率が 80% を超えたカテゴリは注意、100% を超えたカテゴリは超過として目立つ表示になる。

**Why this priority**: 家計簿の「見る」から「行動を変える」への発展。予算の仕組みは自作 API（提案）として発表のネタになるが、無くてもアプリは成立する。

**Independent Test**: 予算を食費 30,000 円とし、食費の支出が 27,000 円の月を表示して「注意（90%）」、31,000 円の月で「超過（103%）」と表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 食費の予算が 30,000 円で今月の食費が 24,000 円, **When** ダッシュボードを開く, **Then** 食費に「80%」と注意表示が出る。
2. **Given** 交通費の予算が 10,000 円で今月の交通費が 12,000 円, **When** LINE で「今月」と送る, **Then** サマリーに「交通費が予算を 2,000 円超えています」が含まれる。
3. **Given** 予算が設定されていないカテゴリ, **When** 表示する, **Then** 使用率は表示せず金額だけを表示する。

---

### User Story 4 - 他の金融機関の支出もまとめて見る（統一 ID 構想） (Priority: P4)

国が発行する統一 ID で、本人のすべての銀行口座・クレジットカード・QR コード決済の明細を横断的に取得できる世界を想定する。ダッシュボードは sunabar の明細に加えて、他の金融機関（ダミー）の明細も合算して表示し、明細ごとに出どころ（どの金融機関か）が分かる。

**Why this priority**: 講座のグランドルール「法整備が遅れている領域に踏み込んでも OK」を活かした発展案。発表のインパクトは大きいが、P1〜P3 が完成してから取り組む。

**Independent Test**: 統一 ID 連携を有効にした状態でダッシュボードを開き、sunabar の明細とダミーのカード明細が 1 つの一覧・グラフに合算され、出どころのラベルが付いていることを確認できる。

**Acceptance Scenarios**:

1. **Given** 統一 ID 連携が有効で、ダミーのクレジットカード明細が今月 3 件ある, **When** ダッシュボードを開く, **Then** 支出合計に 3 件分が加算され、明細一覧で「カード」などの出どころが表示される。
2. **Given** 統一 ID 連携が無効, **When** ダッシュボードを開く, **Then** sunabar の明細だけが表示される。

---

### Edge Cases

- 1 か月の明細件数が、銀行 API の 1 回の取得上限を超える場合（続きのページがある場合）でも、全件を集計する。
- 明細の摘要からカテゴリを判定できない場合は「その他」に分類する。
- 入金（給与・振込入金など）は支出グラフに含めず、入金合計としてのみ扱う。
- つかいわけ口座間の振替など「自分の口座間の移動」は支出として数えない。
- 未来の月、または口座開設前の月を指定された場合は「データがありません」と表示する。
- 銀行 API のトークンが無効・期限切れの場合、ユーザーにはトークン等の内部情報を見せず、「銀行との接続設定を確認してください」と表示し、運用者はログで原因を確認できる。
- 銀行 API の応答が遅い場合でも、LINE への応答が制限時間内に返るようにし、間に合わない場合はエラーメッセージを返す。
- LINE で「今月」「先月」「ダッシュボード」以外のメッセージが来た場合は、使い方（送れる言葉の一覧）を返す。

## Requirements *(mandatory)*

### Functional Requirements

**明細の取得と集計**

- **FR-001**: System MUST 指定した月（1 日〜末日）の入出金明細を銀行 API から取得する。
- **FR-002**: System MUST 取得上限を超える場合は続きを取得し、その月の明細を全件集計する。
- **FR-003**: System MUST 明細を「入金」「支出」に分け、月ごとの入金合計・支出合計を算出する。
- **FR-004**: System MUST 自分の口座間の振替を入金・支出の集計から除外する。
- **FR-005**: System MUST 各支出明細にカテゴリ（食費・日用品・交通・住居・通信・娯楽・振込・現金・その他）を 1 つ割り当てる。
- **FR-006**: System MUST カテゴリを判定できない明細を「その他」に分類する。
- **FR-007**: System MUST カテゴリ別の支出合計と、支出合計に対する割合を算出する。
- **FR-008**: System MUST 日ごとの支出合計を算出する。

**LINE Bot（User Story 1, 3）**

- **FR-010**: Users MUST be able to LINE で「今月」「先月」と送ると、その月のサマリー（入金合計・支出合計・カテゴリ上位 3 つ）をカード形式で受け取れる。
- **FR-011**: Users MUST be able to 文字を入力せず、トーク画面下部のメニュー（リッチメニュー）から「今月の支出」「ダッシュボード」を操作できる。
- **FR-012**: System MUST 想定外のメッセージには、送れる言葉の一覧を返す。
- **FR-013**: System MUST 銀行 API の失敗・タイムアウト時に、ユーザー向けのエラーメッセージを返す（無反応にしない）。

**ダッシュボード（User Story 2）**

- **FR-020**: Users MUST be able to LINE アプリ内でダッシュボード画面を開ける。
- **FR-021**: System MUST ダッシュボードに LINE の表示名を表示する。
- **FR-022**: System MUST カテゴリ別の支出割合をグラフで表示する。
- **FR-023**: System MUST 日ごとの支出推移をグラフで表示する。
- **FR-024**: System MUST 明細一覧（日付・内容・金額・カテゴリ・出どころ）を新しい順で表示する。
- **FR-025**: Users MUST be able to 表示する月を前後に切り替えられる。
- **FR-026**: Users MUST be able to カテゴリを選んで明細一覧を絞り込み、解除できる。
- **FR-027**: System MUST LINE と Bot（User Story 1）で表示する金額と、ダッシュボードで表示する金額を一致させる（同じ集計結果を使う）。

**予算（User Story 3）**

- **FR-030**: System MUST カテゴリごとの月予算を取得できる。
- **FR-031**: System MUST 予算があるカテゴリについて使用率（支出 ÷ 予算）を算出し、80% 以上を「注意」、100% 超を「超過」として表示する。
- **FR-032**: System MUST 超過カテゴリがある場合、LINE のサマリーに超過額を含める。

**他の金融機関の明細統合（User Story 4）**

- **FR-040**: System MUST 統一 ID に紐づく他の金融機関の明細を取得し、銀行 API の明細と同じ形式にそろえて集計に含められる。
- **FR-041**: System MUST 各明細に出どころ（sunabar／他の金融機関名）を保持し、画面に表示する。
- **FR-042**: System MUST 統一 ID 連携の有効・無効を切り替えられる。

**セキュリティ・運用**

- **FR-050**: System MUST 銀行 API の認証情報をユーザーの端末（画面側）に渡さない。
- **FR-051**: System MUST ユーザー向けメッセージ・画面・ログに、認証情報を表示・出力しない。
- **FR-052**: System SHOULD LINE から届いたメッセージが本物の LINE からのものか検証する。

### Key Entities

- **明細（Transaction）**: 1 件の入出金。日付、入金／支出の区分、金額、内容（摘要）、カテゴリ、出どころ（sunabar／他の金融機関）を持つ。
- **月次サマリー（Monthly Summary）**: ある月の入金合計、支出合計、カテゴリ別内訳、日別支出を持つ。LINE の Bot とダッシュボードの両方がこれを表示する。
- **カテゴリ別内訳（Category Breakdown）**: カテゴリ名、支出合計、全体に対する割合、予算、使用率、状態（通常／注意／超過）。
- **予算（Budget）**: 月とカテゴリごとの上限金額。
- **カテゴリ判定ルール（Category Rule）**: 明細の内容に含まれるキーワードと、割り当てるカテゴリの対応。
- **連携口座（Linked Account）**: 統一 ID に紐づく他の金融機関の口座。金融機関名、種類（銀行／カード／QR 決済）、明細の一覧を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーが LINE で「今月」と送ってから、サマリーが届くまで 5 秒以内。
- **SC-002**: リッチメニューを押してからダッシュボードにグラフが表示されるまで 5 秒以内。
- **SC-003**: ユーザーは文字を 1 文字も入力せずに（ボタン操作だけで）今月の支出総額とカテゴリ内訳を確認できる。
- **SC-004**: LINE のサマリーとダッシュボードで表示される入金合計・支出合計・カテゴリ別金額が 100% 一致する。
- **SC-005**: デモ用の明細データのうち 90% 以上が「その他」以外のカテゴリに自動分類される。
- **SC-006**: 初見の人が、説明なしで 1 分以内に「今月いちばんお金を使ったカテゴリ」を答えられる。
- **SC-007**: Day5 の発表で、P1〜P3 のデモを 3 分以内に一通り見せられる。

## Assumptions

- **ユーザーと口座**: 利用者は 1 人（デモ実施者）で、使う銀行口座は sunabar の個人口座 1 つとする。LINE ユーザーごとに別々の口座を紐づける機能は範囲外。
- **本人確認**: 講座のグランドルールにより、厳密な本人確認は行わない。LINE で開いたことだけを前提にする（本番では必要な旨を発表で明記する）。
- **カテゴリ判定**: 明細の内容（摘要）に含まれるキーワードで判定する。精度より「銀行が加盟店情報つきの明細を提供すれば正確になる」という提案に重点を置く。
- **予算**: 予算はあらかじめ決めた固定値とし、画面から編集する機能は範囲外。
- **他の金融機関の明細**: 実在しないため、ダミーデータで代用する（統一 ID 構想の提案として発表）。
- **デモデータ**: sunabar の入金シミュレーターと振込を使い、発表用に 1〜2 か月分の入出金を事前に作成する。sunabar の明細は店舗名を含まないことが多いため、店舗名を含む支出はダミーの他の金融機関の明細で補う。
- **対応環境**: スマートフォンの LINE アプリ（iOS／Android）を主対象とし、PC 版 LINE やブラウザ単体での利用は最低限の表示のみ保証する。
- **期間**: 開発は Day2 午後〜Day5 午前。P1 は Day3 午前、P2 は Day4 中の完成を目標とする。
